# 愈康云诊所（YuKang Cloud Clinic）

> 面向独立诊所与连锁诊所的开源、本地优先一体化经营管理平台。

**当前版本：v5.1.0** · **Windows x64 离线单机版** · **默认端口：3002（占用时自动避让）**

愈康云诊所是一套面向个人医生、单体诊所、连锁总店与分店的管理系统。它将患者接诊、电子病历、电子处方、药房库存、门诊收费、经营统计、AI 辅助诊断、药典知识库和数据备份恢复集中在一个轻量平台中，电脑、手机和平板均可通过局域网访问。

系统采用本地优先设计：核心诊疗和经营数据保存在使用者自己的电脑或服务器上，不依赖第三方云数据库。单体诊所可以直接使用；连锁机构可在总店统一查看各门店的聚合经营数据，并通过邀请码安全接入分店。

> [!IMPORTANT]
> v5.1.0 已完成 EXE 安装、托盘运行、自动端口、异常重启、本地离线资源、备份恢复、换机迁移和签名更新链路等代码基础，但当前仓库不包含 Windows 代码签名证书，默认构建结果是“未签名预览包”，**不能直接作为正式商业安装包大规模推广**。正式交付还必须取得药典数据使用授权，并用 EV/OV 代码签名证书重新构建。完整状态见 [商业发布检查清单](docs/commercial/商业发布检查清单.md)。

## 项目定位

愈康 v5.1 同时解决三类场景：

- **个人医生与单体诊所**：不需要复杂服务器和长期订阅，即可完成日常接诊、开方、发药、收费和统计。
- **连锁总店**：统一管理本组织下的门店账号、分店接入和跨店经营概况。
- **连锁分店**：使用独立门店数据空间开展业务，不越权查看总部或其他分店数据。

项目坚持免费、开源和数据自主管理。代码可查看、修改和二次开发，核心业务数据默认留在本地。

## 功能总览

### 账号、组织与门店

- 注册时填写姓名、手机号、身份证号、诊所名称并确认隐私授权。
- 选择“单体诊所”时自动建立独立门店，不显示连锁管理入口。
- 选择“连锁诊所”时继续选择“总店”或“分店”。
- 总分店机构模型由总店生成一次性邀请码，分店注册后自动加入对应连锁组织。
- 总店负责人拥有独立“门店”控制台，可查看本组织全部门店的经营聚合数据。
- 分店账号不显示门店控制台入口，直接访问接口也会被拒绝。
- 各门店账号、会话和业务数据相互隔离，切换门店不能越权读取其他门店数据。

### 工作台与门诊

- 工作台集中展示今日门诊、患者、待发药、收费和库存预警等关键指标。
- 门诊接诊采用患者列表、病历录入、就诊历史三栏工作台。
- 支持初诊、复诊、医保、自费等业务标识。
- 患者搜索、历史记录、诊断和处方信息可快速联动。
- 接诊完成后可进入待收费、药房发药和经营统计流程。
- 患者列表支持对未收费、未发药记录执行删除，并同步清理关联的待收费和待发药数据。
- 已保存病历支持进入修改模式；保存时会用事务同步更新门诊、患者档案、收费单和药房待发药记录。

### 电子病历与处方

- 完整记录主诉、现病史、既往史、过敏史、体格检查、中医四诊、诊断、辨证和医嘱。
- 现病史、过敏史、体格检查等支持分类症状点选。
- 诊断可根据知识库智能推荐候选病症。
- 处方覆盖中西成药、输注、中药、贴敷、外治等类型。
- 处方药品按类型过滤，只允许选择当前门店可用的药品和库存。
- 处方可批量推送药房并同步扣减库存，重复发药会被拦截。
- 支持一键复制上次处方和常用方剂组套。

### 药房、库存与患者档案

- 药品列表分为物品信息和库存信息，可查看成本、毛利率、批次、效期和供应商。
- 支持库存盘点，录入实盘数后自动计算差异并调整库存。
- 提供无毛利、低毛利、低库存、库存耗尽和效期预警。
- 发药后自动生成出库记录。
- 支持按名称、编码、规格、厂家、供应商、批准文号、批号和单位搜索药品，并可组合药品分类筛选。
- 新入库药品按批准文号、药典精确条目或人工选择归类，使用“中药饮片”“中药配方颗粒”等法定名称；证据不足标为“未归类”，不按名称关键词猜测。Excel 导入同步校验并归类。
- 支持药品和库存数据的 Excel 智能导入导出。
- 患者档案自动归拢历次就诊、诊断、处方、过敏史和既往史。

### 门诊收费与收费单

- 接诊后生成待收费记录，收费成功后才计入正式营收。
- 支持现金、微信、支付宝、银行卡、医保和其他支付方式。
- 支持标准应收、实际收费、顾客付款、优惠减免、找零和调整原因，营收按实际收费入账。
- 支持付款不足校验和重复支付拦截。
- 提供 A4 收费单与 80mm 小票两种打印格式。
- 已收费记录支持查询和补打，打印不会重复计入营收。
- 收费数据进入营收统计、日报和门店经营汇总。

### 经营统计

- 营收概况、收费明细、收费日报和项目统计相互独立。
- 支持库存统计、运营分析、处方量趋势、药品毛利和复诊率分析。
- 总店控制台可查看各门店门诊量、患者数、营收、待收费、待发药和库存预警。
- 总部默认读取聚合经营指标，不复制患者就诊明细。

### AI 辅助诊断与药典知识库

- 结合患者主诉、症状、诊断、本店库存和药典知识生成处方建议。
- AI 审方可检查过敏、配伍禁忌和药物相互作用。
- AI 输出必须由医生确认后才写入正式处方。
- AI 不可用、断网或额度不足时，不影响正常接诊和开方。
- 内置 2305 种单药、112 首方剂和 56 条相互作用。
- 收录四本中国药典 PDF 的 5954 页、14638 条原文知识块，供处方药品详情和 AI RAG 检索。
- 药品悬停可查看药典详情与原文摘录。
- 支持智谱 GLM、DeepSeek、硅基流动和自定义兼容接口。

### 数据备份与一键恢复

- 每个门店每天自动生成独立 SQLite 快照，默认保留最近 60 份。
- 设置页提供图形化备份列表、手动备份和一键恢复。
- 恢复前自动创建当前数据快照。
- 恢复完成后自动执行数据库完整性检查，并返回登录页重新验证。
- 旧版 JSON 数据在首次启动时只读导入，原文件保留用于回滚核对。

## 快速开始

### 客户安装（推荐）

正式交付目录中应包含 `YuKangClinic-Setup-5.1.0-x64.exe`。客户只需双击安装程序，按向导选择安装目录，安装完成后从桌面或开始菜单启动。

1. 运行安装程序并选择安装目录。
2. 首次启动会等待本地服务就绪，然后打开登录页。
3. 关闭主窗口后程序继续在系统托盘运行；右键托盘图标可打开数据目录、备份目录、日志目录、端口设置和开机启动。
4. 手机、平板访问：保持在同一可信 Wi-Fi，打开托盘菜单或“设置”页显示的局域网地址。
5. 换电脑前先在“设置 → 数据备份”执行“导出完整数据”，在新电脑导入；不要直接复制 `clinic_database`。

未签名预览包必须明确标注“仅供内部验收，Windows 可能显示未知发布者”，不能冒充正式签名版。

### 源码运行

要求 Node.js 22.5 或更高版本。

```powershell
Set-Location '愈康项目源码\clinic_system'
npm install
npm start
```

默认访问地址为 `http://localhost:3002`。仅建议开发人员使用源码方式运行，客户交付使用安装包。

## 桌面安装包构建

Windows/Linux 桌面安装包的构建源码位于 `desktop/`。仓库不提交 Electron 运行时、安装包和完整向量知识库。

完整 Windows 商业交付构建统一使用：

```powershell
Set-Location .
powershell -ExecutionPolicy Bypass -File tools\build-commercial-release.ps1
```

该脚本会：

1. 校验主程序与桌面构建版本必须一致。
2. 校验输出目录位于 `D:\`。
3. 将完整知识库、Node 运行依赖、Font Awesome、SheetJS 和二维码能力打入运行时。
4. 调用 electron-builder 生成 NSIS 安装程序。
5. 校验 Authenticode，执行安装包运行时冒烟测试，计算 SHA-256，并生成独立客户交付目录。
6. 调用 `tools/verify-delivery.ps1`，拒绝敏感文件、计划外安装包、漏算文件清单和推广状态矛盾。

交付目录中的 `发布信息/RELEASE_INFO.json` 会记录 `release_channel` 和 `promotion_ready`。未签名构建只能得到 `internal-preview-unsigned`；只有签名有效、药典授权确认和干净虚拟机验收同时完成，才会输出 `commercial-signed`。

当前没有代码签名证书时，只能显式构建未签名预览包：

```powershell
powershell -ExecutionPolicy Bypass -File tools\build-commercial-release.ps1 -AllowUnsigned
```

正式发布时传入受信任证书，脚本会拒绝把未签名结果写成正式包：

```powershell
powershell -ExecutionPolicy Bypass -File tools\build-commercial-release.ps1 `
  -CertificatePath 'D:\ReleaseSecrets\yukang-code-signing.pfx' `
  -DataLicenseConfirmed `
  -CleanVmVerified `
  -CertificatePassword '证书密码'
```

仅构建安装程序、不生成交付目录时，可在 `desktop/` 下执行以下命令；仍需设置完整知识库路径：

```bash
cd desktop
npm ci
npm run install:electron
```

Windows 构建：

```powershell
$env:YUKANG_KNOWLEDGE_DB = 'D:\YukangKnowledge\v5-full\knowledge_index.db'
npm run dist:win
```

Linux 构建：

```bash
YUKANG_KNOWLEDGE_DB=/path/to/knowledge_index.db npm run dist:linux
```

无完整向量索引时可构建精简版：

```powershell
$env:YUKANG_ALLOW_LITE_INDEX = '1'
npm run dist:linux
```

macOS 安装包当前暂缓，构建源码保留。生成文件写入 `desktop/artifacts/`，不纳入 Git。详细说明见 [desktop/README.md](desktop/README.md) 和 [商业化文档目录](docs/commercial/)。

## 官网

公开产品官网位于 [`website/`](website/)，采用独立的静态 HTML/CSS/JavaScript 实现，展示愈康的产品定位、业务流程、核心能力、数据安全边界和部署方式。

当前展示页采用愈康 App 最初的透明切角“愈”Logo，并将登录页的采药背景延展为官网首屏。桌面端提供首屏背景视差、卡片 3D 倾斜与高光、滚动进度和工作流自动轮播；移动端提供简化动效，并遵循系统的“减少动态效果”设置。

```powershell
python -m http.server 4173 --directory website
```

启动后访问 <http://127.0.0.1:4173/>。官网不连接诊所数据库，不提供业务登录入口，也不会上传患者数据。诊所业务系统仍应只部署在本机或可信局域网，不能通过公网反向代理直接暴露。

阿里云 ECS、DNS、安全组、HTTPS 和 ICP 备案的完整上线步骤见 [`deploy/README.md`](deploy/README.md)。当前官网已预部署到阿里云 ECS，临时验证地址为 <http://120.55.116.160/>；`yukangclinic.cn` 的 ICP 备案仍在审核，DNS 和 HTTPS 尚未切换，审核通过前不要把这个临时地址当作正式官网对外发布。

准备服务器公网 IP、SSH 私钥、域名和证书邮箱后，可在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\deploy.ps1 `
  -ServerHost 'ECS 公网 IPv4' `
  -User 'root' `
  -KeyPath 'D:\Keys\aliyun.pem' `
  -Domain 'yukangclinic.cn' `
  -Email '<证书通知邮箱>' `
  -IncludeWww
```

部署脚本只上传 `website/`，使用独立 Nginx 站点和 `/var/www/yukang-site/current` 发布目录，不覆盖服务器上已有站点。

## 技术架构

- **后端**：Node.js 22.5+、Express
- **前端**：原生 HTML、CSS、JavaScript，无大型前端框架依赖
- **主数据库**：SQLite，启用 WAL 模式
- **控制库**：`clinic_database/control/control.db`，保存账号、组织、门店、角色和邀请码
- **门店库**：`clinic_database/stores/<clinic_id>/clinic.db`，每个门店独立隔离
- **兼容库**：`clinic_database/clinic.db` 用于旧版单店数据兼容和历史迁移
- **备份**：各门店独立快照，默认保留最近 60 份
- **默认端口**：`3002`
- **桌面壳**：Electron + electron-builder
- **本地 RAG Worker**：FastAPI + ONNX 向量模型，可选部署

轻量架构的目标是让普通诊所电脑也能稳定运行，同时避免把患者明细集中到外部云平台。

## 数据安全与隐私

- 账号、组织、门店和邀请码保存在本机控制库中，各门店业务数据使用独立 SQLite 数据库。
- 身份证号使用 AES-256-GCM 加密保存，以 SHA-256 指纹校验重复，界面和接口仅展示末四位。
- 密码采用哈希存储，登录使用会话令牌，不保存明文密码。
- 敏感业务集合使用 AES-GCM 加密；Windows 环境下加密密钥由 DPAPI 保护。
- 系统维护防篡改审计链，可检测历史记录被修改。
- 总店控制台只读取本组织门店的聚合业务指标和负责人信息，不复制患者明细。
- 分店账号不能访问总部控制台或其他门店数据。
- 启用第三方 AI 时，处方建议所需的主诉、症状、诊断等片段会发送到所选模型服务商，但不会发送患者姓名和手机号。
- 对“数据不得出域”有硬性要求的机构，应关闭第三方 AI 或改用本地模型。
- `clinic_database/`、备份、日志和原始药典整理数据均已加入 `.gitignore`，不会随源码提交到 GitHub。

### 部署安全边界

- 当前会话主要保存在 Node.js 进程内存中，服务重启后需要重新登录。
- 为了方便局域网电脑、手机和平板访问，HTTP 接口当前允许跨域；系统未提供登录限速、账号锁定和完整 CSRF 防护。
- 仅应部署在本机或可信诊所局域网，不应通过路由器端口映射、公网 IP 或未经鉴权的反向代理直接暴露到互联网。
- 如未来需要公网或跨院区使用，应先补齐 HTTPS、反向代理、登录限速、账号锁定、审计告警、CSRF 防护和渗透测试，再评估上线。

## 可选扩展架构

### 商业云控制面

`cloud_control_plane/` 提供 FastAPI + PostgreSQL 控制面预览，包含组织、门店、成员角色、边缘设备、版本、更新任务、经营汇总、授权和审计日志。它属于可选扩展，诊所主系统不依赖该服务即可运行。

### 本地 RAG Worker

`local_rag_worker/` 使用 `BAAI/bge-small-zh-v1.5` ONNX 模型生成向量。门店文本可留在本地，系统将 SQLite FTS5/BM25 与向量召回通过 RRF 合并；Worker 不可用时自动回退关键词检索，不阻塞接诊。

## AI 使用说明

1. 进入“设置 → AI 配置”，选择服务商并填写 API Key。
2. 点击“测试连接”，确认服务可用后保存。
3. 在门诊选择患者并填写主诉、症状或诊断。
4. 点击“AI 辅助诊断”，核对建议药品、剂量和禁忌后应用到正式处方。
5. AI 只从当前门店库存中选药，医生确认后才写入处方。

第三方 AI 的可用性、额度和数据处理规则由对应服务商决定。关闭 AI 后，系统仍可完整使用病历、处方、药房、库存、收费和统计功能。
